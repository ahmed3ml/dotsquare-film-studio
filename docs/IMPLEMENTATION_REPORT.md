# تقرير التنفيذ — ترقية الاستوديو إلى معمارية «الجودة أولاً» (v1.1)

## 1) ما تم فحصه قبل البناء (قدرات Claude Code المدعومة فعلياً)
المصدر: توثيق Claude Code الرسمي (agent-teams / sub-agents / hooks / skills) عبر وكيل بحث، والإصدار المحلي 2.1.232.
- **Agent Teams: تجريبية ومعطّلة افتراضياً.** تُفعَّل بالمتغير `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. الفريق يُنشأ بلغة طبيعية من القائد وقت التشغيل،
  ولا توجد ملفات تعريف فرق (المجلد `.claude/teams` غير مقروء). أعضاء الفريق يمكن أن يُنشؤوا من تعريفات `.claude/agents` (الأدوات والنموذج تُطبَّق)
  لكن **المهارات (skills) لا تُحمَّل مسبقاً للأعضاء**. فريق واحد لكل جلسة، لا فرق متداخلة، و`/resume` لا يستعيد الأعضاء.
- **قرار:** لم أفعّل الميزة التجريبية. المشروع يعمل بالوكلاء الفرعيين افتراضياً، ويكتشف تفعيل الفرق (`teams check`) ويستخدم الفرق فقط إن فعّلتَها أنت.
- **ترويسة الوكلاء الفرعيين:** `tools`, `model` (sonnet/opus/haiku/fable/ID كامل/inherit), `skills`, `hooks`, `permissionMode`... ؛ **Hooks:** `PreToolUse` بمطابِق `Write|Edit`، الحظر بخروج 2.
  غير مؤكّد عملياً: اسم مفتاح المسار في حمولة Write/Edit (`file_path` حسب الاصطلاح) — الحارس يقبل `file_path` و`path`.

## 2) المعمارية الهجينة (قرار لكل مهمة)
| الآلية | الاستخدام |
|---|---|
| Skills (18) | المعايير والإجراءات وصيغ المخرجات وقواعد الجودة (14 حِرفية + مراجعة/فحص وسائط/إعادة محاولة تكيفية/تنسيق الفرق) |
| Subagents (18) | المهام المحدودة، البحث، التنفيذ، **وكل مراجعة مستقلة** |
| Agent Teams | فقط حيث يلزم تواصل مباشر أو تنافس أو تنسيق متوازٍ: قصة، مخرج+مدير تصوير، منتجا الصورة والفيديو، فحص الجودة — ولكل فريق بديل بوكلاء فرعيين |

الفرق العشرة (سجل `standards/teams.json`، مفحوص آلياً: لا مبدع هو نفسه مراجع، كل فريق له مراجع مستقل ومدخلات ومخرجات واعتماديات وبديل):
البحث التاريخي · تطوير القصة · كتابة السيناريو ومراجعته · الإخراج والتصوير · تصميم الشخصيات والبيئات · لوحة القصة وتخطيط اللقطات ·
توليد الصور والفيديو · الصوت والأصوات · المونتاج والإنهاء · ضمان الجودة المستقل.
لتجنب التكرار: المراجعون يُعاد استخدامهم عبر الفرق (مثلاً continuity-supervisor)، وحذفتُ shot-production-supervisor لصالح image-producer / video-producer / sound-producer / film-editor.

## 3) سياسة النماذج
كل الوكلاء الـ18 على `opus` عبر `standards/model_policy.json` (مصدر واحد، `models check` يكشف أي انحراف، ولا اختيار تلقائي لنموذج أرخص).
**قرار يخصّك:** «الأقوى» غير محددة في بيئتي؛ إن كان `fable` أقوى لديك: `python3 studio/studio.py models apply --model fable`.

## 4) سياسة الجودة — ما يفرضه المحرك فعلياً
- **حلقة مراجعة وتعديل بمعايير قبول** (`standards/criteria.json`، 11 مجموعة معايير تغطي: الدقة التاريخية والمصادر، التماسك الدرامي، اتساق الشخصيات، الواقعية البصرية،
  التكوين السينمائي، جودة الحركة، التشريح، الاستمرارية الزمانية/المكانية، جودة الحوار الإنجليزي، تزامن الصوت، مواصفات التسليم). **بلا درجات رقمية اعتباطية.**
- المراجع ≠ المنتِج (وإلا يتحول الحكم إلى «يحتاج مراجعة بشرية»)؛ كل معيار يحتاج دليلاً محدداً؛ معايير الوسائط لا تنجح بلا **ملفات أدلة** من فحص مباشر؛ ما لا يمكن فحصه = `NOT_VERIFIED` → مراجعة بشرية موثّقة.
- `submit` يُرفض بلا مراجعة مقبولة وحديثة؛ تغيير الملف أثناء المراجعة يُبطلها؛ بعد القبول تصبح قديمة (Stale). **اللقطة لا تصبح APPROVED إلا بمراجعة مقبولة لملف المخرَج نفسه** (وليس بتقرير المنتِج).
- **فحص مباشر:** `inspect` (ffprobe + استخراج إطارات + قياس الصوت وفرق تزامن الصوت/الصورة) و`techcheck` مقابل `delivery_spec`. المراجع يقرأ الإطارات بنفسه؛ المحرك يشترط الأدلة ولا يستطيع إثبات النظر (مذكور في القيود).

## 5) الاقتصاديات
- **لا سقف ثابتاً منخفضاً للمحاولات.** كل محاولة فاشلة تتطلب فئة فشل + تحليلاً؛ ومن الفشل الثاني المتتالي يُطلب `--strategy-change`؛ `hard_cap` اختياري وافتراضه فارغ.
- `GENERATION_LOG.csv`: المزوّد، النموذج، التكلفة، النتيجة، بصمة الملف، علامة synthetic. `report economics`: استخدام النماذج، المحاولات، الفاشلة وتكلفتها، تكلفة المراجعات، المصرَّح به والمتبقي، التقدير المتبقي.
- **التصريح بالصرف منفصل عن الموافقة الفنية:** `cost authorize` (قرارك) يولّد AU-id؛ كل صرف يستهلكه ويُرفض إن تجاوزه؛ مجموع التصاريح ≤ الميزانية المعتمدة؛ اعتماد بوابة لا يمنح صرفاً أبداً.
- أسعار المزوّد مجهولة حتى تزوّدنا بها (null) — المحرك يرفض التخمين.

## 6) المزوّدون (Adapters)
طبقة `studio/providers.py`: إمكانية ← مسار ← مزوّد في `projects/<ID>/providers.json` (استبدال مزوّد = تعديل مسار). الأنواع: prompt-file (الافتراضي، لا توليد → BLOCKED_EXTERNAL_TOOL)،
connector (أداة MCP داخل الجلسة: المحرك يفحص البوابة والتصريح والسعر، والوكيل ينفّذ ثم يسجّل النتيجة الحقيقية)، command (argv بلا shell)، local، mock (وسائط اختبار مُعلَّمة synthetic). لا مزوّد مفترض الاتصال.

## 7) الـ Hooks
`PreToolUse` على `Write|Edit` ← `studio.py hook-guard` يمنع تحرير سجلات المحرك والحالة وملفات التدقيق والملفات المعتمدة المقفلة. `validate` شبكة أمان للتعديل عبر الـ shell.

## 8) مشروع MUTAH-PILOT
رُقّي إلى v1.1 (`upgrade`، سجل CHANGE_LOG). الحالة: GATE-01..09 لم تبدأ؛ لا بحث ولا سيناريو ولا وسائط ولا صرف. الأسئلة المفتوحة Q-001..Q-005 كما هي (الميزانية، الأدوات، سياسة تصوير الصحابة، مراجعة دينية، مواصفات التسليم).

## 9) الاختبارات
70 اختباراً ناجحاً + اختبار دخان شامل (انظر `TEST_RESULTS.md`)، تغطي كل ما سبق، وأحدها يتحقق أن كل أمر مذكور في أوامر الـ slash موجود فعلاً في المحرك.

## 10) ما لم يُتحقَّق منه / غير مكتمل (بصدق)
انظر `LIMITATIONS.md`: لم يُشغَّل فريق وكلاء ولا وكيل ولا hook داخل Claude Code فعلياً؛ مزوّدو الصور/الفيديو/الصوت الحقيقيون غير موصولين ولا أسعارهم معروفة؛
استقلالية المراجع قائمة على الأسماء والتعريفات؛ لا يمكن للنموذج الحكم على أداء الصوت (يُطلب سماع بشري).
